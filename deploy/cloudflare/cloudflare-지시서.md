# Cloudflare 설정 지시서 (브라우저 에이전트용)

## 배경

`pikmindiary.com`은 Cloudflare **무료 플랜**이다. 서버가 통째로 꺼지면 방문자에게
Cloudflare 기본 오류 화면(521/522)이 뜬다. 무료 플랜은 커스텀 오류 페이지 기능이
없으므로, **Worker**를 앞단에 두어 원본 서버에 닿지 않을 때 직접 만든 안내 화면을
대신 내보낸다.

작업은 세 가지다.

1. Worker 생성 + 코드 배포
2. Worker를 두 호스트에 **Route**로 연결
3. Always Online이 **꺼져 있는지** 확인 (켜지 않는다)

---

## 준비

- Cloudflare 대시보드(https://dash.cloudflare.com)에 로그인되어 있어야 한다.
- 대상 존(zone): **pikmindiary.com**
- 붙여넣을 코드 파일: `/home/tori/pikmin-diary/deploy/cloudflare/cf-worker-maintenance.js` (약 6KB)

대시보드 화면 구성은 수시로 바뀐다. **아래 메뉴 이름이 화면과 다르면, 이름이 아니라
목적에 맞는 자리를 찾아서 진행할 것.** 같은 기능이 다른 탭으로 옮겨가 있는 경우가 많다.

---

## 작업 1 — Worker 만들기

1. 왼쪽 메뉴에서 **Workers & Pages** (또는 **Compute**) 로 이동한다.
2. **Create** → **Workers** → 기본 템플릿(Hello World)으로 생성한다.
3. 이름은 **`pikmin-maintenance`** 로 한다.
4. 일단 **Deploy** 를 눌러 생성을 끝낸다. (템플릿 코드가 올라가지만 상관없다)
5. 생성된 워커로 들어가 **Edit code** (또는 **</> Edit**) 를 연다.
6. 편집기 안의 **기존 코드를 전부 지우고**, 위 파일의 내용을 **통째로** 붙여넣는다.
   - 파일 맨 윗줄은 `// 피크민 다이어리 - 서버가 꺼졌을 때 보여줄 안내 화면` 이다.
   - 파일 맨 아랫줄은 `};` 이다.
   - 중간에 백틱(`` ` ``)으로 감싼 긴 HTML이 들어 있다. **한 글자도 빼거나 줄이지 말 것.**
7. **Deploy** 를 누른다.

### 작업 1 확인
- 저장/배포 시 오류 메시지가 없어야 한다.
- 워커 상세 화면에 배포 시각이 방금으로 갱신돼 있어야 한다.

## 작업 2 — Route 연결 ⚠️ 가장 조심할 단계

워커를 두 주소에 붙인다.

1. 워커 상세 → 상단 **Domains** 탭 → **Custom Domains and Routes** → **+ Add Route**
   (문서에는 Settings → Domains & Routes로 적혀 있으나 2026년 5월에 Domains 탭으로 옮겨졌다.
   더 예전 UI라면 Settings → Triggers → Routes)
2. Zone은 **pikmindiary.com** 을 고르고, route 패턴에 아래를 넣는다.

   ```
   pikmindiary.com/*
   ```

   ⚠️ Zone을 고르면 칸이 **`*.pikmindiary.com/*`** 로 자동으로 채워진다. 이건
   서브도메인만 잡는 패턴이라 **정작 `pikmindiary.com` 본주소가 빠진다.**
   앞의 `*.` 을 지우고 위 패턴 그대로 넣을 것.

4. **Failure mode** 선택지가 보이면 **Fail open (proceed)** 로 바꾼다.
   (기본값은 Fail closed (block)이다)
5. 저장한 뒤, 같은 방식으로 하나 더 추가한다. Failure mode는 역시 **Fail open**.

   ```
   www.pikmindiary.com/*
   ```

### Failure mode를 Fail open으로 두는 이유

이 설정은 **워커 자체가 터지거나 한도를 넘겼을 때** 어떻게 할지를 정한다.

- Fail closed (block, 기본값): 워커가 죽으면 사용자에게 오류 → **워커 사고가 사이트 전체 다운이 된다.**
- Fail open (proceed): 워커를 건너뛰고 원본으로 바로 보낸다 → 사이트는 평소대로 뜬다.

이 워커는 "서버가 죽었을 때 곱게 안내하는" 보조 장치일 뿐이다. 그 보조 장치 때문에
멀쩡한 사이트가 막히면 본말전도다. 워커가 고장나면 조용히 비켜서는 쪽이 맞다.

### ⚠️ 반드시 지킬 것

- **"Custom Domain"이 아니라 "Route"로 추가해야 한다.** Custom Domain으로 붙이면
  해당 호스트의 원본이 워커 자체로 바뀌어 **사이트 전체가 망가진다.**
  두 선택지가 나란히 보이므로 헷갈리지 말 것.
- **DNS 레코드는 건드리지 않는다.** 기존 레코드는 프록시(주황색 구름) 상태 그대로 둔다.
- 끝에 `/*` 를 빠뜨리지 않는다.

## 작업 3 — Always Online은 끈 채로 둔다 (확인만)

1. 왼쪽에서 존 **pikmindiary.com** 을 선택한다.
2. **Caching** → **Configuration** 으로 간다.
3. **Always Online** 토글 상태를 확인한다.
   - **꺼져 있으면 그대로 둔다.** (기본값이 꺼짐이다)
   - 켜져 있으면 **끈다.**
4. 그 화면의 다른 항목은 손대지 않는다.

### 왜 켜지 않나

Always Online은 원본이 죽었을 때 인터넷 아카이브에 저장된 예전 페이지를 200으로
대신 내보낸다. 그러면 Worker가 보낸 서브리퀘스트에도 그 200이 돌아와, Worker는
"원본 정상"으로 판단하고 안내 화면 대신 **낡은 좌표 목록**을 그대로 통과시킬 수 있다.

이 사이트는 내용이 계속 바뀌는 좌표 게시판이다. 서버가 죽은 동안 옛날 데이터를
현재인 것처럼 보여주는 것보다, "지금 멈춰 있다"고 알리고 연락처를 주는 쪽이 낫다.
그래서 Always Online은 쓰지 않고 Worker 하나로 통일한다.

## 마지막 확인

브라우저에서 아래를 열어 **평소와 똑같이 보이는지** 확인한다.

- https://pikmindiary.com/
- https://www.pikmindiary.com/
- https://pikmindiary.com/coordinates/

셋 다 정상(좌표 목록이 보이는 평소 화면)이어야 한다.

**만약 "잠시 사이트가 멈춰 있습니다" 안내 화면이 뜬다면 설정이 잘못된 것이다.**
즉시 작업 2에서 추가한 Route 두 개를 지우고(또는 워커를 삭제하고) 보고할 것.

## 하지 말 것

- 유료 플랜 업그레이드, 결제 정보 입력 — 결제를 요구하는 화면이 나오면 **중단하고 보고**한다.
- DNS 레코드 추가/수정/삭제
- SSL/TLS, Security, Page Rules, Firewall 설정 변경
- 다른 존(다른 도메인) 건드리기
- 기존에 있던 다른 Worker 수정/삭제

이 지시서에 적힌 것 외에는 아무것도 바꾸지 않는다.

## 참고 (사람이 읽을 것)

- 워커는 들어오는 요청을 원본 서버로 넘기고, 502/504/520~526이 나거나 아예 닿지 않을 때만
  안내 화면을 503으로 내보낸다. 평상시에는 아무 영향이 없다.
- 같은 존 안에서 워커가 보내는 서브리퀘스트는 워커로 되돌아오지 않고 원본으로 바로 가므로
  무한 루프는 생기지 않는다.
- 무료 한도는 하루 10만 요청. 이 사이트는 하루 약 2.2만 요청이라 여유가 있다.
- 안내 화면 문구나 연락처를 고치려면
  `/home/tori/pikmin-diary/static/maintenance.html` 을 고친 뒤
  `python3 /home/tori/pikmin-diary/deploy/cloudflare/build-worker.py` 를 돌리고,
  워커 코드를 다시 붙여넣으면 된다.
