운영 데이터는 건드리지 않습니다

같은 서버에서 운영 DB와 테스트가 공존하므로, 안전장치를 세 겹으로 뒀습니다. 이게 없으면 테스트를 돌릴 때마다 실제 게시글과 좋아요가 오염됩니다.

  • ✓별도 테스트 DB — Django가 새로 만들고 끝나면 지웁니다. db.sqlite3는 열지도 않습니다.
  • ✓임시 업로드 폴더 — 테스트가 올린 사진은 임시 디렉터리로 가고 끝나면 통째로 지워집니다. media/에 쓰레기가 안 쌓입니다.
  • ✓외부 API 차단 — 좌표를 저장하면 Nominatim으로 지역을 조회하는 시그널이 백그라운드 스레드로 뜹니다. 테스트에서는 막아둡니다. 네트워크가 끊겨도, 상대 서버가 느려도 결과가 흔들리지 않습니다.

자동으로 못 잡는 것

테스트가 통과했다고 화면이 멀쩡하다는 뜻은 아닙니다. 아래는 구조상 기계가 볼 수 없어서 사람 체크리스트로 넘긴 것들입니다.

  • →글씨 대비와 레이아웃 — 흰 배경에 흰 글씨를 서버는 알 수 없습니다. 실제로 지난달 랭킹·안내 페이지 제목이 밤 테마에서 한 달간 안 보이는 상태였습니다.
  • →구글 로그인 왕복 — 구글 서버가 필요합니다. www 주소와 없는 주소 양쪽을 직접 눌러봐야 합니다.
  • →아이폰 HEIC 변환 — 브라우저가 올리기 전에 하는 일이라 서버에서 재현할 수 없습니다.
  • →클립보드 복사 — 좌표가 진짜 붙여넣어지는지는 실제 브라우저에서만 알 수 있습니다.
테스트가 통과한다고 끝이 아닙니다. 자동 테스트는 "적어둔 규칙이 깨지지 않았다"만 말해 줍니다. 적지 않은 규칙은 아무도 지켜주지 않습니다. 새 기능을 만들 때 테스트를 같이 늘려야 그물이 촘촘해집니다.
